About Me

I am a BI Analyst and Systems Architect based in Addis Ababa, Ethiopia. I specialize in the complete data and software delivery lifecycle: querying databases, building star schemas, formulating formal Business Requirements (BRD & RTM), and engineering robust enterprise inventory engines and web applications.

With an academic foundation spanning business operations and information systems, I bridge the gap between executive business needs, compliance mandates (such as Ethiopian VAT & Withholding regulations), and technical software implementations.

These four areas are not separate jobs stitched together. -- Rolling vaccination percentage of population via CTE and window function
WITH pop_vs_vac AS (
    SELECT d.location, d.date, d.population, v.new_vaccinations,
        SUM(v.new_vaccinations) OVER (
            PARTITION BY d.location ORDER BY d.date
        ) AS rolling_people_vaccinated
    FROM CovidDeaths d
    JOIN CovidVaccinations v
        ON d.location = v.location AND d.date = v.date
    WHERE d.continent IS NOT NULL
)
SELECT *, ROUND(100.0 * rolling_people_vaccinated / population, 2)
    AS pct_population_vaccinated
FROM pop_vs_vac 
ORDER BY location, date;

SQL Direct Multi-Table Indicator Join 
-- Recomputing GDP per capita directly from unified population & GDP tables
SELECT
    p."Country Name", p.Year, p.Population, g.GDP_current_USD,
    ROUND(g.GDP_current_USD / p.Population, 2) AS gdp_per_capita_usd
FROM Population p
JOIN GDP g
    ON p."Country Name" = g."Country Name" AND p.Year = g.Year
WHERE p."Country Name" IN ('Ethiopia','Kenya','Uganda','Tanzania','Rwanda')
ORDER BY p."Country Name", p.Year;

// Cryptographic HMAC-SHA256 signature verification & idempotency control
export function verifyChapaSignature(rawBody: string, signatureHeader: string, secret: string): boolean {
  const hash = crypto
    .createHmac('sha256', secret)
    .update(rawBody)
    .digest('hex');
  return crypto.timingSafeEqual(Buffer.from(hash), Buffer.from(signatureHeader));
}

Bill of Materials (BOM) & Relational Prisma Schema

Live Vercel Web App ↗ View schema.prisma on GitHub ↗ View Monorepo Architecture ↗

Every menu item (Espresso, Ethiopian Macchiato, Caffe Latte) is mapped to exact grams of roasted beans, milliliters of milk, syrups, and packaging. When an order is registered, the atomic transaction engine queries the recipe Bill of Materials and depletes inventory from the oldest active batch under First-In, First-Out (FIFO) rules.

Prisma Relational Recipe & Batch Model 
// Kaldi's Multi-Branch Schema (packages/database/prisma/schema.prisma)
model BillOfMaterials {
  id                String          @id @default(uuid())
  finishedProductId String
  rawMaterialId     String
  quantityRequired  Float           // e.g. 18.0 (grams), 240.0 (ml), 1.0 (unit)
  unit              String          // "g", "ml", "unit"
  finishedProduct   FinishedProduct @relation(fields: [finishedProductId], references: [id])
  rawMaterial       RawMaterial     @relation(fields: [rawMaterialId], references: [id])
}

model BatchStock {
  id              String      @id @default(uuid())
  branchId        String
  rawMaterialId   String
  batchNumber     String      // e.g. "BAT-2026-BOLE-089"
  expiryDate      DateTime    // FIFO deduction priority
  currentQuantity Float
  status          String      // "OPTIMAL", "LOW_STOCK", "CRITICAL", "DEPLETED"
}
